# Contributing to pzstudio

Thank you for your interest in contributing to **pzstudio**! Whether you're fixing a bug, proposing a new feature, or improving documentation, your help is welcome.

## Code of Conduct

Please note that this project adheres to a Code of Conduct. By participating, you are expected to uphold respectful and constructive collaboration.

## How Can I Contribute?

### Reporting Bugs
Before creating a bug report, please check the [existing issues](https://github.com/escapepz/pzstudio/issues) to see if the problem has already been reported. If it hasn't, open a new issue and include:
* A clear, descriptive title.
* Steps to reproduce the behavior.
* Expected behavior vs. actual behavior.
* Screenshots, logs, or system/environment details (if applicable).

### Suggesting Enhancements
Enhancement suggestions are tracked as GitHub issues. When opening an issue for a feature request, please provide:
* A clear explanation of the problem you're trying to solve or the workflow you want to improve.
* A description of the proposed solution and any alternative approaches you've considered.

### Pull Requests
1. **Fork the repository** and create your branch from `main` (e.g., `git checkout -b fix/issue-description` or `feat/feature-name`).
2. **Make your changes**, keeping commits focused, atomic, and well-described.
3. **Follow the repository's formatting conventions** (e.g., 2-space indentation where applicable) and ensure all existing tests pass. Add new tests for new functionality or bug fixes.
4. **Update documentation** if your changes affect setup, configuration, or public APIs.
5. **Open a Pull Request** against the `main` branch with a clear summary of your changes and link any related issues (e.g., `Closes #123`).

## Style & Commit Guidelines

* Write clear, concise commit messages using the imperative mood (e.g., `Add user authentication flow`, `Fix crash on startup`).
* Keep pull requests focused on a single concern so they are easier to review.

## Questions?

If you have questions about contributing or need guidance before starting work on a large change, feel free to open an issue to start a discussion.
