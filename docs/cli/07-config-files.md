# 07 — Files and State on Disk

Everything the CLI persists lives in exactly three places: the project folder, the global
`~/.pzstudio` store, and the build output tree.

## Project folder layout (after `pzstudio new`)

```
<project>/
  project.json            ← project manifest (the single source of truth for build)
  workshop/
    description.txt       ← workshop page body (lines → workshop.txt)
    preview.png           ← workshop preview image (optional)
  <modId>/                ← one folder per mod (source of truth for mod content)
    42/                   ← branch folder (name is arbitrary; what matters: has media/)
      media/…             ← Build 42 assets
      mod.info            ← optional; generated by `modinfo generate` / build
    common/               ← another possible branch
      media/…
  .template-mod/          ← seeded local mod template (editable override for `add`)
  .template-language/     ← shared language template (junction or copy)
  .libraries/             ← shared Lua libraries from the project template
  .vscode/                ← produced by the project template (settings, extensions)
```

## project.json

Written by: `new` (created inside staging, committed atomically), `add`, `delete`,
`rename`, `modconfig`, `migrate`.
Read by: every project command (and the experimental gate).

```
{
  "schemaVersion": 2,
  "workshop": { "title": "...", "description": "..." },
  "mods": { "<modId>": { "name": "...", "description": [...], "build": { "devOnly": true, "modInfo": "auto-if-missing" } } },
  "excludes": ["<modId>"],
  "outdir": "relative/or/absolute path",
  "build": { "target": "production|development|both" },
  "pzBuildCompatibility": "42.x",
  "experimental": { "integration": true }
}
```

### `experimental.integration` (CLI-10 — ⚠️ BREAKING: default OFF)

- Optional boolean, also accepted at global level. **Absent = disabled** — the CLI never
  auto-enables experimental behaviour; existing projects created before CLI-10 stop
  getting the experimental script injection silently.
- **Precedence** (`packages/cli/src/lib/helper.ts:662-671`):
  1. `project.json` `experimental.integration` when **present** — `true` and `false` are
     both decisive (explicit `false` in the project overrides a global `true`);
  2. otherwise the global `config.json` value when present;
  3. otherwise `false`.
- Only consumer in the MVP: `updateExperimentalScripts` (the first line of the function,
  `packages/cli/src/lib/helper.ts:690-695`) — see `08-mechanics.md`. No migration needed
  (optional key; `schemaVersion` stays 2).
- Validation for both layers lives in `@pzstudio/core`
  (`validateExperimentalField`, `packages/core/src/validation.ts:478+`) and the JSON
  schema (`pzstudio.schema.json`) declares the property.

Write contract:
- **Atomic**: written to `<file>.tmp` then renamed (direct write fallback on lock/cross-volume).
- **Unknown fields preserved**: a merge with the on-disk content keeps fields the CLI does not know.
- **Validated before write**: modconfig refuses to persist a shape the schema rejects.
- `useSymlinks` is stripped from project.json when encountered (not supported at workspace level).

## Global store — ~/.pzstudio/

```
~/.pzstudio/
  config.json             ← global defaults (templates, outdir, useSymlinks, experimental)
  .pzstudio.bak           ← legacy pre-v0.3 content (only as outdir fallback)
  templates/
    <user>/<repo>/        ← one cache per template source
      …                   ← git clone (has .git) or fetch extraction (has .pzstudio-fetch.json)
  .template-legacy/       ← bootstrapped bundled templates (offline fallback)
    .template-project/ .template-mod/ .template-workshop/ .template-language/
```

### config.json

```
{
  "templates": {
    "project":  { "url": "https://github.com/escapepz/...git", "ref": "42.17.0" },
    "mod":      { … }, "workshop": { … }, "language": { … }
  },
  "useSymlinks": true,
  "outdir": "C:\\Users\\…\\Zomboid\\Workshop",
  "experimental": { "integration": false }
}
```

Behavior notes:
- Created with all defaults on the first *real* command (pure invocations like
  `--help`/`--version` create nothing — CLI-1 contract).
- Migrated automatically at startup when the legacy shape is detected (two reporting
  layers — see `01-root-flow.md`).
- Validation failure on read → warning + in-memory defaults (the corrupt file is NOT
  overwritten except by an explicit `outdir` / `migrate` write).
- Template URL accepts `user/repo`, `user/repo@tag`, `user/repo#branch` and full https URLs;
  only github.com repositories are allowed.
- `experimental.integration` here is the global opt-in fallback for projects that do not
  set the key themselves.

## Build output tree

```
<outdir>/                        ← resolved via the chain (see 02)
  <title>/                       ← main output (production)
    workshop.txt                 ← generated (title, id, description lines, visibility)
    preview.png                  ← copied if present
    Contents/mods/<modId>/<branch>/…    ← Build 42 layout
  <title> - dev_branch/          ← development output
    workshop.txt                 ← title + " - dev_branch" suffix, id + "_dev"
    Contents/mods/<modId>_dev/<branch>/…
```

Planner rules worth remembering:
- A mod folder **with** branch folders containing `media/` → files land under each branch;
  **without** any branch folder → files land at mod root (legacy Build 41 layout).
- Development variant patches `mod.info` content: `id=` line rewritten to `<modId>_dev`
  (applies even when `build.modInfo` is `skip` — skip only means "don't generate").
- `workshop.txt` is an **output artifact** — never watched, never edited by hand;
  its source is `workshop/description.txt`.

## .pzstudioignore

Per-directory ignore file for every copy/scaffold operation (new, add, build, rename).

```
# comments allowed
folder-name/          ← directory prefix match
exact-file.txt        ← exact path match (relative to this file's directory)
```

- The **closest** `.pzstudioignore` up the tree wins (first match stops the walk).
- Hardcoded always-ignored regardless: `.git`, `.github`, `.gitmodules`, `.gitkeep`.
- `.pzstudioignore` itself is carried over during `new` (so user rules survive) but excluded
  from mod scaffolding during `add`/`build` (`excludeIgnoreFile`).
- The watch engine is the one place a dotfile is *not* ignored: a changed
  `.pzstudioignore` triggers a re-sync of its mod (see `04-commands.md` → watch).

## What writes where (matrix)

| File | new | add | delete | rename | modconfig | modinfo | migrate | outdir | build/watch | clean |
|---|---|---|---|---|---|---|---|---|---|---|
| `<project>/project.json` | ✔ create (via staging) | ✔ | ✔ | ✔ | ✔ | — | ✔ | — | — | — |
| `<project>/<modId>/**` | ✔ create (via staging) | ✔ create (+rollback) | ✔ delete | ✔ move+rewrite | — | mod.info only | — | — | — | — |
| `<project>/package.json` scripts | ✔* | ✔* | ✔* | ✔* | — | — | — | — | — | — |
| `.template-mod/` | ✔ create | ✔ seed (when cache absent) | — | — | — | — | — | — | — | — |
| `~/.pzstudio/config.json` | — | — | — | — | — | — | ✔ | ✔ | — | — |
| `~/.pzstudio/templates/**` | cache/clone | cache/clone | — | — | — | — | — | — | cache/clone (workshop) | — |
| `~/.pzstudio/.template-legacy/**` | bootstrap (first legacy need) | same | — | — | — | — | — | — | same | — |
| `<outdir>/**` | — | — | — | — | — | — | — | — | ✔ full ownership | ✔ delete only |

`*` = only when `experimental.integration` is opted in (default OFF — BREAKING, CLI-10).

Read-only commands regardless of flags: `list` (human and `--json`), `doctor` (human and
`--json`). `delete`/`rename` with `--dry-run` write nothing. No command other than the
ones above writes to the project or the store.

`build`/`watch`/`clean` own the output tree exclusively: everything under `<outdir>/<title>*`
is deleted and re-created; manual edits there are lost by design.
