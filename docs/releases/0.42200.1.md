# `@pzstudio/cli` 0.42200.1

Stream-contract fix and packaging/docs cleanup. No breaking changes to the
API surface, the JSON contract, or the exit-code matrix.

## What's changed

### Intentional stream normalization (CLI-2)

The **pinned contract is `progress → stderr`, `data/result → stdout`**:

- **stdout** carries command data and results: `list`/`doctor`/`migrate`/
  `modinfo` reports, dry-run `Would:` plans, the `new` golden-path `Next:`
  block, per-command verdicts (`Added mod …`, `Already clean.`,
  `Clean complete in …s!`, `project.json updated.`, …), the banner/help, and
  the `--json` envelopes. A successful `pzstudio build` prints **nothing** on
  stdout.
- **stderr** carries everything a human watches while the command runs:
  `Building main workshop...`, `Cleaning … directory...`,
  `Deleting mod …`, `Renaming mod …`, `Refreshing/Updating templates...`,
  template clone/scaffold steps, watch banners and sync summaries, warnings,
  diagnostics and errors. This also covers the VS Code extension's auto-sync,
  which shares the sync engine's log forwarding.

Machine consumers are unaffected: `--json` remains a strict `JSON.parse` of
stdout, and pipes/CI see the same plain-text bytes as before — only the
channel assignment of progress lines changed.

**Timestamps, colors and the `[INFO]` prefix are presentation, not stable
API.** They are gated on the target stream being a TTY and may change at any
time; pin channel + semantic text, never exact formatting.

### Packaging cleanup

- `dist/pzstudio.cmd` is no longer produced. The stray wrapper (with a
  `pause` prompt) shipped inside the npm tarball and was never part of the
  supported surface — npm/pnpm generate their own platform shims from the
  `bin` entry. A clean build and the packed tarball contain no
  `pzstudio.cmd`.

### pnpm guidance

- The README now spells out the two pnpm mental models: `pnpm dlx` runs the
  package anywhere (ephemeral), while `pnpm add -D` + `pnpm exec` runs the
  pinned version where the local dependency is installed — pnpm does not
  walk up the directory tree like npm, so run `pnpm exec` at the install
  root.
- pnpm (v10+) blocks install scripts by default. The native `@parcel/watcher`
  binding used by `pzstudio watch` needs its build script; the README
  documents the one-time remediation: `pnpm approve-builds @parcel/watcher`
  (the approval persists in the project config as `allowBuilds`; approve only
  the packages you trust, no `--all`).

### First-run template note

- On first use, `new` downloads the current templates from GitHub. Use
  `--offline` to scaffold from the bundled templates without network access
  — now stated up front in the README quick start.

## Compatibility

- `@pzstudio/cli/api` exports and the root-import rejection
  (`ERR_PACKAGE_PATH_NOT_EXPORTED`) are unchanged.
- Exit codes are unchanged: usage errors exit 2, runtime failures exit 1,
  success exits 0, interrupted `watch` exits 130 with exactly one
  `Development sync stopped.` message.
- The VS Code extension bridge is unchanged (it bundles the CLI's `api`
  surface; auto-sync progress now reaches the output channel through the
  same stderr-routed logger).
