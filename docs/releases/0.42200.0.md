# `@pzstudio/cli` 0.42200.0

Initial public release of `@pzstudio/cli`.

## What's changed

### Package name

The CLI has been reorganised from an internal package into the public npm package
**`@pzstudio/cli`**. The binary remains `pzstudio`.

- Published package: `@pzstudio/cli` (not `pzstudio-cli`)
- Embedder import: `require('@pzstudio/cli/api')`
- **There is no supported package-root library import** — always import from `@pzstudio/cli/api`.

### Breaking changes

- **Experimental integration defaults OFF.** The experimental integration features
  (`experimental.integration.*`) are now opt-in. Previously they were enabled by
  default. Set `experimental.integration: true` in `project.json` to re-enable.
- **Embedded delete/rename require `--yes`.** The destructive commands `delete`
  and `rename` refuse to run without explicit confirmation intent in embedded
  (library) and non-interactive sessions — the refusal is a usage error
  (exit 2). Pass `--yes` once your host UI has confirmed, or use `--dry-run`
  to preview.
- **Usage errors exit 2.** Bad arguments — unknown command or flag, wrong
  arity, conflicting flags, or a destructive command refused for lack of
  confirmation — exit with code 2. Runtime failures (missing files, build
  errors, doctor blockers) still exit 1. This allows hosts to distinguish
  usage errors from runtime failures programmatically.
- **Migration/progress output to stderr.** `doctor` and migration output that was
  previously interleaved with data on stdout is now emitted to stderr, keeping
  `--json` output on stdout pure and machine-parseable.

### Requirements

- **Node.js 20 or higher** is required (previously Node 18 was tolerated).

## Quick start

```bash
# Zero-install — no repo clone needed
npx -y @pzstudio/cli@latest new "My First Mod"
cd <path printed by the command>       # e.g. my_first_mod
npx -y @pzstudio/cli@latest doctor     # verify setup
npx -y @pzstudio/cli@latest watch      # start the dev watcher
```

Or with the API:

```js
const { runCLI, runProjectDoctor } = require('@pzstudio/cli/api');
```

## Known limitations (P1 backlog)

- **Transactional rename/delete** — rename and delete are not atomic on
  failure; an interrupted operation may leave partial state. Acceptable for
  a first release because both commands sit behind explicit consent and
  `--dry-run`, run at low frequency, and sit outside the
  `new → doctor → watch` golden path; a proper fix needs
  transaction/staging.
- **Template cache staging** — templates are cloned directly; no staging
  commit guards against interrupted clones (an invalid cache is detected and
  re-cloned on the next run).
- **Clean destructive-consent gate** — `clean` removes both owned
  build-output trees without the shared destructive-confirmation gate used
  by delete/rename. Acceptable for the first release because the output
  tree is generated content owned exclusively by build/watch/clean — source
  and project files are outside that ownership boundary. Revisit for
  consistency.
- **Extension integration docs** — `docs/ext` for the VS Code extension integration is
  deferred post-release.

## Full command reference

| Command | Description |
|---------|-------------|
| `new <name>` | Scaffold a new mod project |
| `doctor` | Verify project structure and toolchain |
| `build` | Build the mod once into the configured `outdir` (default `~/Zomboid/Workshop`) |
| `watch` | Watch source files and rebuild on change |
| `modinfo` | Generate `mod.info` files for your mods |
| `list` | List all discovered projects |

Run `pzstudio --help` for the full reference, or `pzstudio <command> --help` for
command-specific options.
