# `@pzstudio/cli` 0.42220.1

The sweep-hardening release: 27 findings from an end-to-end e2e sweep
campaign are fixed across the engine and the extension — silent failures
now warn or refuse loudly, every consent surface honors
`pzstudio.confirmBeforeRun`, and the everyday commands gain
machine-readable `--json` envelopes. No breaking changes to the JSON
contract, the exit-code matrix, or the stream contract.

## What's changed

### Added

- **`--json` envelopes for `build`, `migrate` and `update`**: the
  structured envelope family `doctor` and `logs` already print now covers
  the everyday commands (the migrate envelope also carries the mod.info
  payload-sync result as `syncedModInfoFiles`).
- **`usage export --json`**: the export reports its result as a JSON
  envelope next to the zip bundle it writes.
- Extension-side: **success toasts for `new` / add / clean** — the
  silent-success commands confirm completion ("PZStudio: project
  created." / "mod added." / "output cleaned."), fired only on actual
  success.
- Extension-side: **`rename` honors `pzstudio.confirmBeforeRun`** — the
  same consent ladder as build/clean/delete (disabled → skip, dismissed
  → abort, never → persist and proceed); `--yes` still bypasses.
- **`.gitignore` is now honored as a rule source** next to
  `.pzstudioignore` on every surface (build copy, watch, development
  sync, project explorer) through the unified ignore engine in
  `@pzstudio/core` — within one directory `.gitignore` entries apply
  first and `.pzstudioignore` second, so `.pzstudioignore` keeps the
  higher precedence at the same level; across directories the closest
  rule file to an entry decides.
- **Real gitignore semantics are active** — wildcard entries (`*.log`,
  `**/temp/**`) match at any depth below the rule file, `!keep.txt`
  negation re-includes what an earlier rule ignored, and `/old.lua`
  anchors at the rule file's directory; all three were dead literals
  under the previous prefix matcher. Plain entries are unchanged (a
  bare `entry` still matches the file or folder of that name at the
  rule file's own level, a folder with its whole subtree, never a
  same-name basename deeper down), and trailing slashes are still
  stripped at parse, so `build/` also excludes a same-level **file**
  named `build` (kept for backward-compat with existing fixtures).
  Safety rails unchanged: rules only ever hide or copy-filter — they
  can never hide `mod.info` or the `.pzstudioignore`/`.gitignore` files
  themselves, the watch/devsync output protection sits above the rule
  matcher, a `.gitignore` is always read as rules even under the build
  copy's dot-file option, and there are no changes to the JSON
  contract, the exit-code matrix, or the stream contract.
- Extension-side: **status-bar Development Sync indicator** — a muted
  `$(circle-slash) DevSync off` while off, `$(sync~spin) DevSync:
  <project folder>` while a run is in flight, with a per-phase tooltip;
  clicking it runs the `pzstudio.watch` toggle phase-gated (start only
  from idle, stop while syncing, queued stop while starting, no-op
  while stopping), and the Project Explorer view shows a `1` badge with
  a per-phase tooltip while a run is in flight.

### Fixed

- Extension: **modinfoGenerate no longer fails with "No pzstudio project
  found"** — the target's project directory is injected context-aware
  through `generateForMod` / `generateForAll` instead of falling back to
  the legacy base directory.
- Extension: **Development Sync delivers again** — the watcher runs a
  self-owned Node `fs.watch` recursive leg alongside
  `vscode.FileSystemWatcher`, which silently ignores trees that appear
  after its setup (project directories and workspace-folder bases
  alike); watcher failures surface instead of stalling at zero delivery.
- **`migrate` keeps root-level `authors`**: a single migrated mod adopts
  them, otherwise they are kept verbatim with a notice — and `migrate`
  now validates its own output before declaring success.
- **`description` survives migrate → generate**: the empty string counts
  as "not carried", so a legacy import no longer overwrites the field
  with the placeholder, and generation emits it whenever present.
- **`rename` no longer loses subdirectories silently** — see Changed
  below: old-id subdirectories are named in a warning, never dropped
  without a trace.
- **`update` cache and legacy refresh use a staged swap**: the old copy
  is removed only after the replacement is fully secured, so an
  interrupted update can no longer leave a poisoned or half-written
  cache — failures leave the previous cache untouched and warn.
- **Copy-mode prune warns with full paths**: every pruned hand-edited
  file is named on stderr (plus a total line) instead of a silent
  delete.
- **`buildplan` aggregates name the missing mod** in the error (survivors
  still build) and print a summary line on `--both`.
- **`add` duplicate refusal exits with a typed `CliError`** instead of
  the catch-all "Unexpected error:", echoing the typed id and its
  normalization.
- **Invalid enum values exit 2 on every path**: the handler sites
  (materialize, usage action, visibility, modinfo, modconfig) match the
  parse stage's code and wording; the messages name the accepted
  aliases.
- **`add --yes` is refused** ("not applicable to command [add]") instead
  of being silently ignored — the global flag stays reserved for the
  commands that consume it (delete / rename).
- Extension: **delete honors `pzstudio.confirmBeforeRun`** through the
  shared confirm helper (scope build / clean / delete), persisting the
  bypass like build and clean.
- CLI quick-wins: the `watch` stop message notes the exit-130 path,
  `usage export` acknowledges `--purge` outside `off`, empty `meta` is
  omitted from usage events, `update` output names the cache directories
  and per-category end states across both roots, `clean` enumerates
  every removed path, and `migrate` warns on missing required fields
  (`name`, `description`).
- **Docs**: the deploy guide explains the reconcile stale window —
  rebuilt item slots reconcile automatically, a slot whose mod is gone
  must be removed by hand.

### Changed

- **`rename` no longer renames subdirectories carrying the old mod id.**
  The sweep made the rename cover them completely (depth-unlimited,
  fail-closed); the owner's re-decision keeps that coverage as a
  warn-only behavior: every affected subdirectory is reported with its
  full path and left untouched. User-designed skeleton directories are
  the user's to manage — the game does not require them to follow the
  id.
- **Materialize boundary gate (data safety)**: an `outdir` equal to the
  project root or lying inside the canonical `dist/` root is refused
  (`DEPLOY_ROOT_INVALID` — hard error in build/watch, error finding in
  doctor) instead of writing links or copies into the source tree; an
  `outdir` equal to `dist/` itself stays pure-build mode (skip +
  `OUTDIR_ALIAS_DIST` info). Watch no longer materializes variants with
  an empty included-mod set (dangling junctions), a locked deployment
  slot no longer erases the doctor's workshop findings
  (`INSPECT_FAILED` per item), and generic copy-slot reconcile failures
  report `RECONCILE_FAILED` — never the healthy `COPY_SLOT` label.
- Extension: **the Development Sync toggle no longer shows success
  popups** — "Development sync started." / "Development sync stopped."
  are gone; the status-bar indicator is the run's source of truth (the
  start-failure toast is kept). Stopping while the initial build is
  still running is queued and honored once the build settles (the
  just-started session does not survive the request), and a start from
  a non-idle phase fails honestly instead of re-anchoring the in-flight
  run. Sync error notifications gain a 'Stop Sync' action next to
  'Show Details', safe to click at any time; indicator strings ship
  English-only for now — the translation bundles gain them (and drop
  the two retired popup strings) at the next translation regen pass.
- Extension: **the PZ Project Explorer hides entries matched by ignore
  rules** (`.gitignore`/`.pzstudioignore`) — the same visual treatment
  as dot entries — with rule-read failures failing open (every child
  shown); a declared mod folder hidden by rules stays "seen": hidden,
  not reported as missing on disk.
