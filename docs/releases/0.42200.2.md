# `@pzstudio/cli` 0.42200.2

Safety-first engine release: output adoption becomes fail-closed inside the
mod source tree, build and clean mutations are alias-route guarded, the
standalone mod flows are hardened, and the host API gains the v2 instance
surface. No breaking changes to the JSON contract, the exit-code matrix, or
the stream contract.

## What's changed

### E1 Stage-1 ownership guard — fail-closed destinations inside the mod source tree

When the build output root sits inside a configured mod folder (including
nested variant layouts), build and rebuild now **refuse to adopt — delete,
replace or overwrite — destinations whose content the engine cannot prove it
created**: the offending content is preserved and reported
(`result.errors`), never silently destroyed. The refusal happens before any
mutation, so a refused batch leaves the disk exactly as it was. Empty
destinations still adopt normally.

If your output folder is **outside** the project (the common layout),
behavior is unchanged in this release — external output roots keep the
previous adoption semantics as a recorded deviation until the full
ownership ledger lands (doc 18, `DR-E1-OB`).

### Alias-route mutation guard (F23-WRITE P0)

- `pzstudio build` and `pzstudio clean` refuse to delete or write through a
  symbolic link or NTFS junction **below** the configured output root: the
  refusal names the offending link before anything is touched, so a
  mutation can never land behind an alias into content the plan never
  spelled. A junction configured **as** the output root keeps working
  (intentional alias resolution).
- The build's copy never re-enters its own destination chain: output roots
  nested inside the source tree no longer self-embed (bounded one-
  generation garbage), including case-variant paths on case-insensitive
  filesystems.

### Add/Delete flow hardening (R1.2-P)

- Add and Delete preserve the configured raw `outdir`; snapshots are
  fail-closed before any project-domain mutation.
- Missing or blank mod IDs are derived safely; normalized-empty
  identifiers are rejected.
- Cancelled prompts abort without fallback or engine execution; New Project
  records the destination only after creation is verified on disk.

### Host API — v2 instance surface

- `@pzstudio/cli/api` adds `createPzStudio(...)`: an instance API with
  explicit-context cores (devsync, doctor, modinfo) and
  `studio.resolveOutDir(projectDir)` for hosts. Legacy exports remain
  functional; nothing is removed.

### What is intentionally NOT in this release (C-17 / DEC-7b)

- **Logs and engine records are retained indefinitely in this version** —
  no retention, rotation or cleanup is performed automatically. The
  ownership-ledger run-log rotation gate (C-17) is deferred with this
  disclosure; a future retention mechanism will never remove ownership
  evidence.

## Compatibility

- `@pzstudio/cli/api` exports are additive (`createPzStudio`,
  `resolveOutDir`); the root-import rejection (`ERR_PACKAGE_PATH_NOT_EXPORTED`)
  is unchanged.
- Exit codes are unchanged: usage errors exit 2, runtime failures exit 1,
  success exits 0, interrupted `watch` exits 130 with exactly one
  `Development sync stopped.` message.
- The stream contract is unchanged: `progress → stderr`, `data/result →
  stdout`; `--json` remains a strict `JSON.parse` of stdout.
- The VS Code extension **0.42200.1** bundles this engine.
